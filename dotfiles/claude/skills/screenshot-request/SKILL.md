# Screenshot requests

## Ask for only what is missing

Review the evidence already available. Ask only for views that would show something useful the existing evidence does not show.

For each requested capture, name the app, view or tab, and exact state; the text, rows, or values that must be visible; and what the capture will show. Give a suggested filename and save directory. List the planned arrows and text labels, if any, and say you will add them.

Ask the user only to capture and save unedited originals and tell you the actual filenames. Look for those names in the authorized location and accept them as saved. Don't ask for renames, cropping, arrows, desktop moves, or browser-panel retries when you can handle the next step. Don't use native desktop control without separate authorization.

## Prepare copies in the background

Open the saved files with supported image tools that don't take desktop focus. Check each against the capture request. If a required view, row, or value is missing, ask only for the missing evidence. Never generate or reconstruct evidence.

Keep the originals untouched. Use available deterministic crop, arrow, and text tools on separate copies. Keep evidence text and numbers visible and unchanged. Put arrows and labels in blank space, or use a caption if there is no room. When pixel comparison is appropriate, compare protected regions in each original and edited copy, accounting for the crop offset. Visually inspect the final copies.

If you are using Monosnap at the user's request and with the required permissions, it copies the edited image. After an authorized paste and verification, close the image window, not the app, before another capture.

## Publish only with authorization

Preparing screenshots does not authorize upload or publication. Use only supported controls to upload the verified final copies to the authorized destination. If an authorized browser action needs to move from a side chat, follow the shared **in-app browser access from a side chat** rule.

For an authorized edit to a pull request comment, re-read the exact pull request and comment, the current draft or ready state, and the latest comment body. Leave readiness unchanged. Edit that comment in place, keep the existing text and evidence, and add captions that explain what the new images show. Don't create a duplicate comment.

After any authorized upload, independently check that the saved images load and render at the destination. Report where the files are, what you changed and checked, and any limits. If a tool or action isn't supported, preserve the prepared files and name the exact step still pending.
