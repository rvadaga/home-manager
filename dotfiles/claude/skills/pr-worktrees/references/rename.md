# Rename one review worktree in place

Use this only when asked to rename a specific existing review checkout. It is not part of ordinary PR sync.

1. Verify the PR, owning chat, old and intended new paths, Git registration, exact HEAD, branch or detached state, and clean status. Check that the destination is unused. Before moving, confirm that this Desktop host supports updating the owning chat's attachment to the exact new path without creating another checkout. Stop if the name or attachment update is unsupported.
2. Check active and archived chats for saved working directories at or below the exact old root. If the user also asks to coordinate a blocked rename, use an agreed, existing checkout as the temporary destination. With permission to message the verified claimants, ask those chats to change their own working directory; do not force a change on their behalf. If the owning chat is using the old path, move it through a supported action too. Read back each saved path and recheck claims immediately before renaming. If a chat is archived, refuses, still claims the path, or cannot be verified, leave the checkout in place and report the reason with a link to each verified blocker, as for blocked archives.
3. In a separate stable checkout of the same repository, use Git's in-place worktree move for the verified paths if Git and the app support the move. Do not force it, clone, archive and restore, or edit app storage. Verify that the old path is gone and exactly one Git registration points to the new path with the same worktree Git directory, HEAD, branch or detached state, and clean status.
4. Use the supported Desktop attachment update. Read back the owning chat's attachments and verify the new path and absence of the stale old path. Update the existing PR-to-checkout record after verification. Check the native PR-to-worktree association separately using the main skill. If the app refuses after Git succeeds, report where the checkout is and which attachment is stale; do not create a replacement or claim that opening a panel fixed it.
